# Day 19 理论笔记：综合 · 端到端交付

## 1. 端到端交付要素：代码 + 环境 + 文档

**概念**：FAE 交付一个项目，不是"发一堆代码"，而是三件套——可运行代码（做什么）、Dockerfile（环境怎么装）、部署说明 README（怎么跑）。三者缺一不可：只有代码别人跑不起来（环境不对），只有环境没有文档别人不知道怎么用，只有文档没有代码是空谈。本案例完整交付了 infer_api.py + Dockerfile + README。

**为什么重要**：这是 FAE 岗位的核心交付能力。客户（或协作团队）拿到项目后，照着 README 两条命令（build + run）就能跑起来，才叫交付完成。"在我机器上能跑"不是交付，是甩锅。

**踩坑**：只给代码不给 Dockerfile，客户环境差异导致"你那里能跑我这里报错"，来回扯皮。README 写得太简略（只有命令没有说明），别人不敢用也不会用。三件套的版本要一致——代码改了，Dockerfile 和 README 也要同步更新。

---

## 2. FAE / 模型部署工程师交付物清单

**概念**：标准交付物清单包括——推理服务代码、容器化定义（Dockerfile）、部署说明（README）、健康检查接口、测试用例/接口文档。本案例里的 `/health` 接口就是运维标配，`HEALTHCHECK` 指令让 Docker 自动探测服务死活，接口说明表格让调用方一目了然。

**为什么重要**：这套清单是昇腾 FAE 交付推理系统的标准配置。面试官问"你交付过什么项目"，能按这个清单讲清楚，就是加分项。开学后的 CANN 工具链学习，最终交付也是这个形态。

**踩坑**：漏掉健康检查接口，服务挂了监控系统无感知，等用户投诉才知道。接口文档不写清楚请求/响应格式，调用方（前端、其他系统）不知道怎么对接。交付物要"自包含"——不能依赖"你脑子里记得的东西"。

---

## 3. 可复现性（reproducibility）为何重要

**概念**：可复现性指"任何人按你的文档操作，都能得到一致的结果"。它靠三样东西保证——环境固化（Dockerfile 锁死依赖版本）、流程文档化（README 写清步骤）、代码版本化（Git 管理）。本案例就是可复现的：任何人 clone 代码，`docker build` + `docker run`，得到完全一样的推理服务。

**为什么重要**：这是工程能力的核心体现，也是选拔评分里"端到端可运行项目"的破格加分项。AI 项目特别强调可复现——模型推理结果必须稳定一致，不能"这次跑对下次跑错"。可复现 = 可信任 = 可交付。

**踩坑**：依赖不锁版本（Dockerfile 里写 `pip install torch` 不写版本号），几个月后装到新版本行为变了，复现失败。环境变量、随机种子不定，推理结果每次不同，无法复现。文档和实际操作不一致（文档写了但没真跑过），交付后客户照着做会卡住。

---

## 4. 复盘：环境 → 数据 → 容器 → 推理全链路

**概念**：前 18 天的学习串成完整链路——环境（Day 1-7 的 Linux/Shell/网络）、数据（Day 8-10 的 Python 数据处理）、容器（Day 11-15 的 Docker）、推理（Day 16-18 的框架/HTTP/监控）。今天把它们整合成端到端项目。这条链路正是昇腾 FAE 的真实工作流：接手环境 → 准备数据 → 容器化 → 交付推理服务。

**为什么重要**：单点技能（会写脚本、会 Docker）是零散的，串成链路才是"会干活"。Day 19 的价值在于让前面所有知识产生了联系——你知道为什么 Dockerfile 里要 `COPY` 那个 Python 脚本，为什么服务要暴露 8000 端口，为什么要有 `/health` 接口。

**踩坑**：只会单点技能，面试被问"完整交付一个项目怎么做"就卡壳。链路里任何一环薄弱都会拖累整体——环境没配好，数据准备好也跑不起来；容器不会打，推理服务只能在你电脑上跑。
