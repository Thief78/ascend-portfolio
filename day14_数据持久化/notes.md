# Day 14 理论笔记：Docker 数据卷（Volume）

## 1. 持久化问题：容器删除后数据丢失

**概念**：容器是"无状态"的——容器的文件系统是临时的，`docker rm` 删除容器后，容器内写的所有文件全部消失。这是 Docker 的默认设计：容器只负责计算，用完即毁。但模型推理需要加载数据集、产出推理结果，这些数据必须"活过"容器的生命周期。

**为什么重要**：不理解这一点会犯严重错误——把训练好的模型、用户数据直接存进容器，结果容器一删，成果全没。数据持久化是生产环境容器的第一课。

**踩坑**：容器内 `pip install` 的东西、跑出来的结果，只要没挂卷或没 commit 成镜像，`docker rm` 后全部丢失。不要以为"容器停了数据还在"——stop 只是暂停（数据还在），rm 才是删除（数据消失）。

---

## 2. Volume vs Bind Mount

**概念**：Volume（命名卷）由 Docker 托管，存在 `/var/lib/docker/volumes/`，你只需指定卷名，不用关心实际位置。Bind Mount（绑定挂载）直接挂载你指定的宿主机绝对路径。两者语法都是 `-v 卷名或路径:/容器内路径`。区别：Volume 更安全、可移植、由 Docker 统一管理，是官方推荐方式；Bind Mount 更直观，直接看到宿主机目录，适合开发调试。

**为什么重要**：生产环境用 Volume（数据交给 Docker 管，备份、迁移方便），开发调试用 Bind Mount（本地改代码，容器立即生效，不用重新构建镜像）。本案例两种都演示了——Volume 验证持久化，Bind Mount 验证内外共享。

**踩坑**：Bind Mount 必须用**绝对路径**，相对路径会报错。挂载目录时，如果容器内路径原本有内容，会被宿主机的目录"盖住"（隐藏），不是合并。Windows 上 Bind Mount 的路径写法（`C:\data`）和 Linux（`/data`）不同，Docker Desktop 里要配置共享目录。

---

## 3. docker volume 命令

**概念**：`docker volume create 卷名` 创建命名卷，`docker volume ls` 列出所有卷，`docker volume inspect 卷名` 查看卷详情（实际存储路径等），`docker volume rm 卷名` 删除卷，`docker volume prune` 清理所有未被使用的卷。不指定名字直接 `-v /路径` 挂载会创建"匿名卷"（随机名字）。

**为什么重要**：卷是独立于容器的资源——删容器不会删卷，卷可以挂在多个容器间共享。掌握 volume 命令才能管理数据卷的生命周期。

**踩坑**：`docker rm` 删容器不会自动删卷，匿名卷会越积越多占磁盘，要定期 `docker volume prune` 清理。删除卷前确认没有容器在用，否则数据丢失无法恢复。命名卷比匿名卷好管理，生产环境一定要用命名卷。

---

## 4. 计算存储分离理念

**概念**：容器只负责计算（无状态、可随时销毁重建），数据外置到卷里（持久化、独立生命周期）。这是"计算存储分离"架构——计算层和存储层解耦，各自独立扩展、独立备份、独立故障。呼应昇腾算力中心的建设要点：容器无状态，数据外置。

**为什么重要**：这是云原生架构的核心思想。容器可以随意扩缩容、滚动更新（计算层弹性），而数据始终在卷/外部存储里（存储层稳定）。FAE 交付推理服务时，模型和数据放卷里，容器本身可以随时更新替换，不影响数据。

**踩坑**：违背这个理念会把数据绑死在容器上，导致无法升级容器、无法多副本部署、数据丢失风险高。设计服务时先问"哪些数据需要持久化"，再决定挂什么卷、挂在哪里。
