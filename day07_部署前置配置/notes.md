# Day 7 理论笔记：Linux 网络·DNS / 防火墙 / 镜像源

## 1. DNS 原理：/etc/resolv.conf、/etc/hosts、解析流程

**概念**：`/etc/hosts` 是本地静态域名映射表，可手动自定义域名与 IP 的对应关系，优先级高于 DNS 服务器。`/etc/resolv.conf` 是系统 DNS 配置文件，记录上游域名解析服务器地址。完整解析流程：程序发起域名查询 → 优先读取本地 hosts 匹配 IP → 无匹配则向 resolv.conf 内的 DNS 服务器发送解析请求 → DNS 返回域名对应的公网 IP。

**为什么重要**：服务器访问外网、拉取代码、安装 pip/apt 依赖、模型下载全部依赖域名解析。解析链路断了，什么都装不了。

**踩坑**：DNS 服务器故障时，hosts 内记录的域名仍可正常访问，容易混淆故障定位方向——排查时要分清"是 DNS 服务器挂了"还是"某个域名没解析"。

## 2. 防火墙 ufw + systemctl 启停与开机自启

**概念**：ufw 是 Ubuntu 系统简化版防火墙工具，底层封装 iptables，用于管控服务器入站/出站网络访问。`ufw allow 端口/tcp` 放行指定 TCP 端口外部访问，`ufw delete allow 端口/tcp` 删除放行规则，`ufw enable` 启用防火墙并设置开机自启，`ufw disable` 关闭防火墙，`ufw status` 查看当前所有放行/拦截规则。`systemctl enable/disable ufw` 可独立控制防火墙开机自启状态。

**为什么重要**：服务器上线安全必备操作。防火墙隔离非法 IP、陌生端口访问，降低服务器被扫描、入侵风险。遵循"只开放必须的端口，剩余默认拦截"的最小开放原则。

**踩坑（今天真实操作的）**：开启防火墙前未放行 22 端口会直接断开 SSH 连接，远程服务器彻底无法登录——所以正确顺序一定是**先 `ufw allow 22/tcp`，再 `ufw enable`**。

## 3. 代理与镜像源：pip/apt 国内镜像配置

**概念**：镜像源是国内机构定时同步海外官方软件仓库、提供国内 CDN 加速下载的节点，分 apt 系统软件源和 pip Python 包源。代理（HTTP/HTTPS）作为中转节点，本机所有网络请求经代理服务器转发，用于访问外网受限资源。配置原理：修改对应工具的配置文件，把默认官方仓库地址替换为国内镜像地址，工具下载时直接请求国内加速节点。

**为什么重要**：海外官方源国内访问延迟高、丢包严重，安装深度学习框架、Python 依赖、系统更新耗时极长。配置清华/阿里镜像源可大幅提高下载速度。内网无外网的服务器可配置代理实现软件包下载。

**踩坑**：apt 与 pip 镜像源不可混用——Debian/Ubuntu 系统不能替换为 CentOS 源，会破坏系统依赖。代理与镜像源同时配置时可能产生冲突，会优先走代理转发流量。

---

## 4. SSH 进阶：端口修改、免密登录、SSH 隧道/端口转发

**概念**：修改 SSH 端口——编辑 sshd 配置文件更换默认 22 端口，降低暴力扫描攻击概率。密钥免密登录——本地生成 RSA 密钥对，公钥上传至目标服务器 authorized_keys，无需密码远程连接。SSH 隧道/端口转发——通过 SSH 通道把本地端口流量转发至远端服务器端口，或远端端口映射至本地，可穿透内网访问无公网的推理服务。

**为什么重要**：生产环境安全加固必改 SSH 默认端口。多台训练机集群运维用免密登录实现自动化脚本批量执行。内网推理服务器无公网 IP 时，依靠 SSH 端口转发在外网本地访问模型接口。

**踩坑**：修改 SSH 端口后，防火墙未同步放行新端口，会导致远程 SSH 连接失败。免密登录失败大多是 `.ssh` 目录、`authorized_keys` 文件权限过宽，SSH 安全机制直接拦截。
