# Day 13 理论笔记：Dockerfile

## 1. 指令：FROM / RUN / COPY / ADD / WORKDIR / ENV / EXPOSE / CMD / ENTRYPOINT

**概念**：`FROM` 指定基础镜像，是构建的起点。`WORKDIR` 设置工作目录，后续指令在此目录执行。`COPY 宿主机路径 容器路径` 把文件复制进镜像。`ADD` 类似 COPY，额外支持解压 tar 和远程 URL。`RUN` 在构建时执行命令（如 pip install）。`ENV` 设置环境变量。`EXPOSE` 声明容器监听的端口（文档性质）。`CMD` 容器启动时默认执行的命令。`ENTRYPOINT` 定义容器的固定入口命令，`CMD` 提供默认参数。

**为什么重要**：Dockerfile 是"镜像即代码"的体现——把环境搭建过程固化成可版本管理的文本，任何人拿到都能 `docker build` 出完全一致的镜像。这是 FAE 交付推理服务的核心能力，也是"可复现性"的基础。

**踩坑**：`COPY` 和 `ADD` 的区别——能用 COPY 就别用 ADD（ADD 的隐式解压行为容易带来意外）。`RUN` 每条命令都会生成一个镜像层，多个 RUN 应该用 `&&` 合并成一条，减少层数。

---

## 2. CMD vs ENTRYPOINT

**概念**：`CMD` 提供默认命令/参数，运行 `docker run 镜像 额外参数` 时可以被覆盖。`ENTRYPOINT` 定义固定的入口，不易被覆盖，`CMD` 作为它的默认参数。两者组合的经典用法：`ENTRYPOINT ["python"]` + `CMD ["infer.py"]`。

**为什么重要**：理解两者区别才能正确设计镜像。纯执行型程序（跑完就退出的脚本）用 CMD 就够了；服务型程序（像守护进程一样常驻）常用 ENTRYPOINT 保证启动命令不被用户误改。

**踩坑**：`CMD ["python", "infer.py"]` 是 exec 形式（推荐），`CMD python infer.py` 是 shell 形式——shell 形式会套一层 `/bin/sh -c`，信号处理有差异。`docker run 镜像 其他命令` 会覆盖 CMD，但不会覆盖 ENTRYPOINT。

---

## 3. 镜像分层缓存与构建优化

**概念**：Dockerfile 每条指令生成一个镜像层（layer）。构建时 Docker 逐层检查缓存——某层的输入（指令 + 依赖文件）没变，就复用缓存层，跳过重新执行。所以"越不常变的放前面，越常变的放后面"是构建优化的黄金法则。

**为什么重要**：合理的指令顺序能极大加速构建。把 `COPY requirements.txt` + `RUN pip install` 放在 `COPY . .` 之前，改代码时依赖层走缓存、只需重建最后几层，构建从几分钟变几秒。

**踩坑**：把 `COPY . .` 放在最前面，后面任何代码改动都会导致所有层失效重来。`docker build` 卡住往往是在等缓存或拉基础镜像，`--no-cache` 可强制全新构建（调试时用）。

---

## 4. 多阶段构建（减小镜像体积）

**概念**：一个 Dockerfile 里写多个 `FROM` 阶段，前一阶段负责编译/安装，后一阶段只复制前阶段产出的最终文件。最终镜像只包含运行必需的东西，编译工具、中间产物全部丢弃。

**为什么重要**：Python 应用如果直接 `pip install` 进镜像，会把源码、编译工具都带进去，动辄上 GB。多阶段构建能让最终镜像缩小数倍。昇腾推理镜像尤其需要——基础 PyTorch 镜像本身就有几 GB，能用多阶段省一点是一点。

**踩坑**：多阶段构建用 `FROM ... AS 阶段名` 命名阶段，用 `COPY --from=阶段名 源 目标` 跨阶段复制。最后阶段只保留运行时的最小依赖，别忘了把必要文件（模型、配置文件）也 COPY 进来。
