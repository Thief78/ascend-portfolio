# Day 2 理论笔记：Linux 权限 / 用户 / 软件包

## 1. 权限模型：rwx 与数字表示

**概念**：权限分三组——属主、属组、其他人，每组由 3 位字符组成。r=读(4)、w=写(2)、x=执行(1)。755 = rwxr-xr-x（属主全权限，属组/其他人只读+执行），644 = rw-r--r--（属主可读写，其他人只读），777 = rwxrwxrwx（所有人都能读写执行，危险）。

**为什么重要**：文件权限直接关系到服务器安全。权限设错，任何人都能修改你的文件，甚至拿到服务器控制权。

**易错点**：遵循"最小权限原则"——只赋予完成任务所必需的最小权限。进入目录需要 x（执行）权限，列出目录内容需要 r（读）权限。只有 r 没有 x 的目录，无法 cd 进入，只能看到文件名列表。`chmod -R` 递归改权限需慎用。

---

## 2. chmod/chown/chgrp + sudo 提权原理

**概念**：`chmod 权限值 文件` 改权限位，`chown 所有者:组 文件` 改所有者，`chgrp 组名 文件` 改所属组。sudo 是以 root 身份启动一个子进程执行命令，系统通过 `/etc/sudoers` 确认用户是否有提权资格。

**为什么重要**：sudo 隔离风险——开发/运维人员不需要知道 root 密码，用自己账号临时提权，操作可追溯。生产环境出事故时，日志能精确找到是谁在什么时间执行了什么高危命令。

**易错点**：绝对不能直接用文本编辑器打开 `/etc/sudoers`，必须用 `visudo`。因为 visudo 会做语法校验，写错了会报错并阻止保存，防止 sudo 失效导致系统彻底无法管理。脚本里写到 `/etc/sudoers.d/` 目录下更安全，配合 `NOPASSWD:` 实现免密提权。

## 3. 用户与组管理

**概念**：`useradd -m` 创建用户并自动建家目录。`groupadd` 创建组。所有用户信息存在 `/etc/passwd` 中。

**为什么重要**：每个服务用专用用户跑，实现权限隔离——一个服务被黑不会波及全局。这是 Linux 服务器安全的基本功。

**易错点**：`useradd` 不加 `-m` 不会自动建家目录，新用户登录会报错。不要用 vim 手动改 `/etc/passwd` 来修改 UID/GID——如果只改了文件的 UID 但没同步修改文件系统中所有该用户文件的 UID，这些文件就变成了无人认领的孤儿文件。正确做法是使用 `usermod -u 新UID 用户名` 和 `groupmod -g 新GID 组名`，它们会自动递归修改该用户所有文件的 UID/GID。

## 4. 包管理与国内源配置

**概念**：`apt install` 安装/升级软件，`apt update` 刷新软件源列表，`apt remove` 卸载软件。`dpkg` 用于离线安装本地 `.deb` 包，`apt` 用于在线安装和依赖管理。国内镜像源通过 Rsync 同步协议每隔几小时从官方源全量拉取软件包，并提供国内 CDN 加速。

**为什么重要**：官方源服务器在海外，国内访问延迟高、丢包严重。接手新机器后换国内源是标准第一步，避免后续安装软件时超时失败。

**易错点**：改配置前先备份（脚本里用 `cp xxx xxx.bak.$(date +%Y%m%d)` 带上日期后缀）。`apt remove` 卸载软件时会保留配置文件，可能导致残留配置与新版不兼容——彻底重装时要使用 `apt purge`。**绝对不能混用 Ubuntu 和 Debian 的源**：核心系统库会被修改，系统命令将全部报错，只能重装系统。
