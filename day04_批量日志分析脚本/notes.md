# Day 4 理论笔记：Shell 变量 / 条件 / 循环 / 函数

## 1. Shebang 与脚本执行
**概念**：`#!/bin/bash` 是 Shebang（释伴行），告诉系统用哪个解释器执行脚本。`chmod +x` 赋予可执行权限后，才能 `./script.sh` 直接运行。
**为什么重要**：没有 Shebang，系统不知道用 sh、bash 还是 zsh 来跑脚本，不同 shell 语法有差异，可能导致脚本报错。
**踩坑**：写完脚本忘加 `chmod +x` 是最常见的低级错误。Windows 上写的脚本换行符是 `\r\n`，传到 Linux 会报 `/bin/bash^M` 错误，用 `dos2unix` 转一下。

## 2. 变量与特殊变量
**概念**：`var="value"` 定义变量（等号两边不能有空格），`$var` 或 `${var}` 取值。特殊变量：`$0`（脚本名）、`$1/$2`（位置参数）、`$#`（参数个数）、`$?`（上条命令退出码，0=成功）、`$$`（当前 PID）。
**为什么重要**：脚本要处理不同的输入就必须用参数。`$?` 是错误处理的依据——判断上一条命令是否成功再决定下一步。
**踩坑**：`var = "value"`（加了空格）会把 var 当作命令执行。取变量时如果变量值含空格，必须加双引号：`"$var"` 而非 `$var`——不加引号会被 shell 按空格拆成多个参数。

## 3. 条件判断与循环
**概念**：`if [ 条件 ]; then ... elif ... else ... fi` 做条件分支。`[ ]` 和 `test` 等价，常见判断：`-z "$str"`（字符串空）、`-f "$file"`（文件存在）、`"$a" == "$b"`（字符串比较）。循环：`for i in 列表; do ... done`、`while [ 条件 ]; do ... done`。
**为什么重要**：条件判断是脚本"大脑"——根据参数决定走哪条路。循环是"自动化的手"——批量处理 100 个文件不可能手动一个一个来。
**踩坑**：`[` 后面和 `]` 前面必须有空格——`if [ "$a" == "$b" ]` 写成 `if ["$a"=="$b"]` 会报语法错。数字比较用 `-eq/-ne/-gt/-lt`，不能直接用 `==`。

## 4. 函数定义与参数
**概念**：`func_name() { ... }` 定义函数。函数内用 `$1/$2` 获取传入参数（和脚本参数语法一样，但作用域不同）。`local var` 声明局部变量，只在函数内可见，不污染全局。
**为什么重要**：函数让脚本可以"分块写、复用调"，避免同一个逻辑复制粘贴十几次。`local` 防止变量名冲突——你在函数里改了 `name`，函数外不受影响。
**踩坑**：函数内忘了用 `local`，变量会变成全局的，在复杂的脚本中很难排查。函数的 `return` 只能返回数字（0-255），返回字符串需要用 `echo` + 命令替换 `$(...)`。
