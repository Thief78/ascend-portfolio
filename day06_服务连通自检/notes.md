# Day 6 理论笔记：Linux 网络·接口 / 诊断

## 1. 网络基础：IP / 子网掩码 / 网关 / DNS / 端口 / TCP vs UDP

**概念**：IP 是主机在局域网/互联网中的唯一标识，分公网 IP 和内网 IP，用于设备间寻址。子网掩码划分 IP 内的网络位与主机位，区分同一网段、跨网段设备。网关是不同网段通信的中转出口，本机访问外网必须经过网关转发。DNS 是域名解析服务，把域名（如 baidu.com）翻译成 IP 地址。端口是一台服务器内区分不同服务的逻辑编号（0~65535），同一 IP 下靠端口区分 SSH、Web、推理服务。TCP 面向连接，三次握手建立通信，可靠传输、有重传、有序，适合网页/SSH/接口服务；UDP 无连接、无握手校验，速度快但可能丢包，适合视频流、实时语音。

**为什么重要**：是服务器部署推理、Web、数据库服务的底层基础。IP、端口、协议三者决定了"谁能访问什么服务"。

**踩坑**：DNS 异常会出现"IP 能访问服务、域名却打不开页面"的情况。网关填写错误会出现"能 ping 通同网段机器，但无法访问外网"的情况。

---

## 2. 接口配置：ip addr / ip link / Netplan

**概念**：`ip addr` 查看本机所有网卡、IP 地址、网卡状态。`ip link` 管理网卡硬件状态，可启用/关闭网卡、修改网卡名称。Netplan 是 Ubuntu 新版系统默认网络管理工具，通过 yaml 配置文件设置静态 IP、网关、DNS，执行 `netplan apply` 生效配置，无需重启服务器。

**为什么重要**：服务器固定 IP 是线上业务刚需，推理、数据库服务不能每次重启变更 IP。运维排查网络不通时，先用 `ip addr` 确认网卡 IP 是否正常；多网卡机器区分业务网、管理网，依靠 ip 系列命令管理。云主机、本地训练机配置静态 IP 均使用 Netplan。

**踩坑**：静态 IP 网段与网关不匹配，会造成本机仅能内网访问、无法访问外网。

## 3. 诊断工具：ping / traceroute / ss / netstat / curl / wget

**概念**：`ping` 发送 ICMP 数据包，测试本机到目标 IP/域名是否基础连通。`traceroute` 追踪数据包路由路径，定位网络中断在哪一跳网关。`ss -tlnp` 替代老旧的 netstat，查看本机 TCP 监听端口、对应进程 PID，高效排查端口占用。`netstat` 是旧版端口查看工具，资源开销更大，现已推荐用 ss 替代。`curl` 是 HTTP 接口探测工具，可查看响应头、获取状态码、测试接口可用性。`wget` 多用于下载网络资源，也可简易测试 HTTP 服务连通。

**为什么重要**：服务故障排查全套工具链——ping 确认底层网络通断，ss 检查服务端口是否正常监听，curl 验证 HTTP 推理接口是否可用。本次端口自检脚本核心依赖 ss 和 curl。线上服务 502、连接超时、端口占用问题全部依靠这套工具定位。

**踩坑**：ping 不通不代表服务不可访问——部分服务器防火墙禁用 ICMP 包，会屏蔽 ping 但 TCP 端口正常。`ss` 不加 `-tlnp` 会看不到监听端口或进程名。curl 默认输出页面内容，搭配 `-s -o /dev/null` 屏蔽输出、仅保留状态码用于脚本判断。

---

## 4. 常见端口：22 / 80 / 443 / 8080

**概念**：22 是 SSH 远程登录端口，用于服务器远程连接、文件传输 scp/sftp。80 是 HTTP 标准网页端口，明文访问 Web 服务。443 是 HTTPS 加密网页端口，SSL/TLS 加密传输。8080 是常用自定义 Web/后端推理服务端口，开发环境、测试服务普遍使用。

**为什么重要**：防火墙放行、端口自检脚本、安全加固都需要熟记标准端口。远程管理服务器必须开放 22 端口。前后端推理服务、测试接口大多部署 8080，线上正式业务改用 443 加密端口。

**踩坑**：防火墙未放行对应端口时，`ss` 显示端口监听，但外部机器无法访问。多服务共用端口会端口冲突、启动失败，需用 `ss` 快速排查占用进程。
