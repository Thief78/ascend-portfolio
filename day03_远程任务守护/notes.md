# Day 3 理论笔记：Linux 进程 / 远程连接

## 1. 进程概念：PID / 前后台 / ps / top / kill / nohup

**概念**：PID 是操作系统为每个运行程序分配的唯一编号，用于标识和管理进程。命令末尾加 `&` 可放入后台，终端可继续输入指令。`ps` 静态打印当前进程快照，`top`/`htop` 动态实时监控 CPU、内存占用。`kill` 通过 PID 发送信号终止进程。`nohup` 让进程脱离终端会话，关闭窗口后程序不会中断，默认输出保存至 `nohup.out`。`jobs` 仅查看当前终端内放入后台的任务列表。

**为什么重要**：深度学习训练、大模型推理、数据同步等长时间任务都需要后台执行。远程 SSH 连接服务器训练时，断开会话会终止前台进程，nohup 可以保障任务持续运行。通过 PID 和 ps/top 可以定位卡死、资源占用过高的训练程序，使用 kill 释放硬件资源——这是 AI 开发、服务器运维的必备操作。

**踩坑**：仅用 `&` 后台运行不搭配 nohup，关闭 SSH 窗口进程会直接终止。nohup 不重定向日志会自动生成 `nohup.out`，长期运行会占用大量磁盘，务必手动指定日志文件（`> train.log 2>&1`）。

## 2. 系统信息：uname / df / du / free / nvidia-smi

**概念**：`uname` 查看系统内核版本、架构、主机名。`df` 查看磁盘分区整体挂载、总容量和剩余空间。`du` 统计单个文件夹/文件实际占用磁盘大小。`free` 展示物理内存与交换内存的总量、已用和空闲。`nvidia-smi`（及昇腾的 `npu-smi info`）实时查看 GPU/NPU 显存占用和利用率。

**为什么重要**：训练前先查磁盘够不够放数据集，内存够不够加载模型。nvidia-smi/npu-smi 是 AI 开发者的第一诊断工具——模型报 OOM 时第一眼看显存占用。

**踩坑**：`df` 和 `du` 结果不一致时不要慌——`df` 统计分区总空间，`du` 统计目录文件大小，差值中包含了系统预留缓存，不是磁盘坏了。

## 3. SSH 原理：密钥认证 vs 密码 / 免密登录 / scp

**概念**：密码认证依靠账号密码校验，安全性低；密钥认证使用 RSA/ED25519 非对称加密，本地保存私钥，远端服务器存储公钥，加密匹配后完成登录，无需输入密码。免密登录流程：本地生成公私钥对 → 将公钥写入目标机器 `authorized_keys` → 本地私钥与远端公钥加密校验，完成免密连接。`scp`/`sftp` 是基于 SSH 协议的文件传输工具。

**为什么重要**：服务器、训练机批量运维场景频繁需要远程登录。密码登录存在暴力破解风险，密钥免密既安全又能自动化执行远程脚本、分布式训练任务。scp/sftp 用于本地与服务器之间上传数据集、下载训练权重、同步代码文件。

**踩坑**：公钥写入文件时必须用 `>>` 追加，用 `>` 覆盖符会清空原有授权密钥，把别人的免密全搞没。重装系统或换客户端后公私钥不匹配，需重新推送公钥。

## 4. ~/.ssh 目录与 authorized_keys

**概念**：`~/.ssh` 是当前用户专属 SSH 配置目录，存放私钥 `id_rsa`、公钥 `id_rsa.pub`、`known_hosts`（记录已信任主机指纹）和 `authorized_keys`。`authorized_keys` 存储所有允许免密登录本机的客户端公钥，SSH 服务校验外来连接时读取该文件匹配密钥。

**为什么重要**：是所有 SSH 免密登录、远程文件传输的核心配置目录。多开发人员共用训练服务器时，把每个人的公钥追加进 `authorized_keys`，即可实现全员免密登录、统一管控访问权限。

**踩坑**：`authorized_keys` 权限必须是 600（仅属主可读写），其他人有任何权限时 SSH 会直接拒绝密钥登录。手动编辑 `authorized_keys` 时换行、空格格式错误，会导致对应密钥失效、免密登录失败。
